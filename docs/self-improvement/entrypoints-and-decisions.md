# 自我完善入口与人工决策点（v1）

> 本文件定义**触发、授权、停止条件与人工决策目录**。任务状态机、路径 / 资源锁、证据矩阵与合并门只在 [`kit/orchestration.md`](../../kit/orchestration.md) 定义；本文件只引用章节，不复制规则。
> 更新入口的流程细节见 [update-safety.md](update-safety.md)；Lesson 状态见 [lesson-lifecycle.md](lesson-lifecycle.md)。

## 1. 触发语与非触发

### 1.1 “进行自我完善”

以下表达（大小写、空格、标点无关）路由到同一流程：

- `进行自我完善` / `自我完善`
- `根据其他 AgentOrch 项目的经验改进本项目`
- `总结近期开发教训并推进改进`

判定规则：

1. 必须有**明确的执行意图**（祈使句、或用户要求 Agent 现在去做）。只有名词短语的提问（如“自我完善机制是怎么设计的？”）只做解释，不启动流程。
2. 触发后仍按当前 edition 恢复状态并走正常任务流程；触发不等于批准任何具体改动。
3. 同一会话重复触发不重复创建任务：先恢复未结候选与现有任务，报告“无新增候选”。
4. 用户话术与当前项目无关（例如在别的项目里谈 AgentOrch 设计）时只回答，不落地改动。

### 1.2 “更新 AgentOrch”

- 触发：`更新 AgentOrch` / `升级 AgentOrch` / `把项目中的 AgentOrch 更新到最新版`。
- 非触发：`更新一下文档` / `更新依赖` / `更新这个 Issue` / 仅询问版本号。
- 歧义时先问一次“是更新套件本身还是更新项目内容”，不得默认执行套件更新。

### 1.3 共同规则

- 触发语必须存在于**正式发行包会包含的入口 / edition 文件**；只写在 `docs/`（不随包发布）不算接入（由 #52 落地）。
- 触发不改变 `docs/PROJECT.md` 的 `edition` 优先级，也不允许跨底座混用载体。

## 2. 自我完善流程（引用式）

1. **恢复真实状态**：项目配置、规则、任务载体、`git status --short`、当前 head SHA、最近任务、未决阻塞。证据取当前底座载体，不用聊天记忆。
2. **读取有效来源**：按 [sources-and-trust.md](sources-and-trust.md) 加载注册表；空注册表 → “无来源可扫描”报告；配置非法 → 失败关闭。
3. **增量采集**：按游标与 `lookback_days` 读取允许证据；不可达 / 无权限按 §4 记录 `BLOCKED` / `UNKNOWN`。
4. **候选与验证**：按 [lesson-lifecycle.md](lesson-lifecycle.md) 分类、定证据等级、去重、记录冲突。
5. **覆盖检查**：对照现有契约 / 代码 / 测试 / 流程，判断是否已被覆盖；已覆盖只记证据或建议补测试。
6. **成本收益与方案**：为目标、非目标、根因、收益、成本、风险、允许路径、验收、负向场景、迁移 / 回滚给出方案。
7. **登记任务**：在阶段计划与任务载体中登记；字段与门禁按 `kit/orchestration.md` 4.1，不新增第二套。
8. **按锁与依赖派发**：路径 / 资源锁、依赖 `VERIFIED`、并行度按机器余量；不共享可写 Worktree。
9. **独立审查与验证**：Master 按 G1–G6 逐门审查；执行者不自批、不自合；head 变化后重新取证。
10. **闭环报告**：已完成、已创建任务、阻塞、未验证能力、当前 SHA、每项证据链接；`NOT_RUN` / `BLOCKED` 明确标注。

## 3. 授权模型

| 行为 | 是否需要人工决策 | 说明 |
|---|---|---|
| 只读采集、分类、报告 | 否 | 受来源注册表与访问权限约束 |
| 记录候选 Lesson、去重、标冲突 | 否 | 不代表采纳 |
| 生成低风险、可回滚、路径不冲突的改进方案与任务 | 否（在既有权限内） | 仍需 Master 审查与合并门 |
| 修改安全 / 权限边界、锁 / 状态机、数据格式、外部依赖、隐私边界、兼容性 | **是** | `HD-05` |
| 采纳通用教训且影响上述边界 | **是** | `HD-03` |
| 合并 PR、批准验收、关闭 Issue、标 `VERIFIED` | **是（仅 Master / 所有者）** | 执行者永远不得 |
| 修改 AgentOrch 权威规则（`AGENTS.md`、`kit/`、`editions/`）以“吸收教训” | **是** | 走正常 Issue + 审查，不得由来源内容驱动 |

触发语**不等于**无条件授权。默认不自动合并、不绕过审查门、不推送破坏性更改。

## 4. 停止条件

出现以下任一情况，停止推进并记录状态（`BLOCKED` 或 `NEEDS_HUMAN_DECISION`），不得降级为“先做了再说”：

1. 注册表缺失 / 非法 / schema 版本不支持。
2. 来源不可达且报告需要该来源结论。
3. 候选证据不足以支撑任何结论，且用户要求“必须给出改进”。
4. 同一教训产生冲突且无裁决。
5. 改进触及权限 / 安全 / 锁 / 状态机 / 迁移 / 外部依赖 / 兼容性，尚未决策。
6. 触发的改进需要超出任务允许路径。
7. 当前 head 上的必需检查未通过或无法运行。
8. 运行时不具备派发能力（C1–C4 未通过），按核心契约降级为人工交接。
9. 采集内容疑似含凭据、个人数据或受版权文本。
10. 请求的更新来源不是官方 Release（见 update-safety.md §2）。

停止时必须写明：观察事实、依据的门 / 契约条款、已尝试措施、恢复条件、需要谁决定。

## 5. 人工决策目录（唯一权威）

决策 ID 全局唯一，其它文档只引用 ID，不重定义。记录位置：Issue 评论 / PR 评论 / 决策日志；必须含问题、选项、决定人、时间、影响任务。

| ID | 触发情形 | 需要决定的问题 | 选项（至少两个） | 决定人 | 未决时阻塞 |
|---|---|---|---|---|---|
| `HD-01` | 新增 / 启用 `authorized_private` 来源，或改变既有 `source_id` 指向 | 是否授权访问？授权范围与证据范围？ | 授权并登记 / 暂不登记 | 项目所有者 | 该来源的采集与结论 |
| `HD-02` | 移除来源、清空注册表，或游标倒退无法解释 | 是否删除条目？历史 Lesson 如何归档？ | 停用保留 / 删除（保留历史）/ 删除并归档 | 项目所有者 | 后续扫描与相关报告 |
| `HD-03` | 把 Lesson 提升为 `GENERAL_LESSON`，且影响安全 / 权限 / 锁 / 状态机 | 是否接受该通用规则？适用范围？ | 接受 / 限定范围 / 拒绝 | 项目所有者（可委托架构审查） | 泛化与任务生成 |
| `HD-04` | 两条 Lesson 冲突（`CONTRADICTS` / `SUPERSEDES` / `OVERLAPS`）无法靠证据解除 | 采信哪一方？适用条件如何划界？ | 以证据 A 为准 / 以证据 B 为准 / 划界并存 | 项目所有者 | `GENERALIZED` / `IMPLEMENTED` |
| `HD-05` | 改进会改变权限、安全边界、锁、状态机、数据格式、外部依赖、隐私或兼容性 | 是否做？范围与回退？ | 批准 / 缩小范围 / 拒绝 | 项目所有者 | 方案与任务 |
| `HD-06` | 威胁模型存在未缓解的剩余风险，或用户要求跳过某项缓解 | 是否接受剩余风险？是否补偿控制？ | 接受并记录 / 增加缓解 / 不做该功能 | 项目所有者 | 对应实现任务 |
| `HD-07` | 目标 Release 是预发布或非 stable 通道 | 是否允许安装非 stable？ | 允许（记录理由）/ 只等 stable | 项目所有者 | 更新流程 |
| `HD-08` | 旧 Format / 缺少基线 MANIFEST / 版本不支持 | 是否手工迁移？迁移路径？ | 手工迁移 / 暂不更新 | 项目所有者 | 更新应用 |
| `HD-09` | 上游删除或重命名项目内仍存在的文件 | 删除、保留还是改名？ | 保留并告警 / 手工删除 / 改名迁移 | 项目所有者 | 清理与应用 |
| `HD-10` | `THREE_WAY_CONFLICT`（本地与上游都改） | 逐文件：保留本地 / 采用上游 / 手工合并 / 延后 | 逐文件选择 | 项目所有者 | 该文件应用 |
| `HD-11` | 回滚失败或回滚后校验仍失败 | 如何恢复？是否继续更新？ | 从备份人工恢复 / 保留现场等待排查 / 重新安装 | 项目所有者 | 后续任何更新 |
| `HD-12` | 工作区有未提交改动且无法安全隔离 | 是否允许在现有工作区继续？ | 先提交 / 新建 Worktree / 推迟更新 | 项目所有者 | 更新应用 |
| `HD-13` | schema / Architecture Contract 的破坏性版本升级 | 是否升级？迁移方案？ | 升级并迁移 / 保持旧版 / 拒绝 | 项目所有者 | 相关实现 |
| `HD-14` | 为项目启用 Architecture Contract `ENFORCE`（首次硬门禁） | 是否阻断 CI？规则与豁免范围？ | 启用 / 先 DIAGNOSTIC / 不启用 | 项目所有者 | CI 门禁 |
| `HD-15` | 新增外部工具链依赖（如 Rust、第三方验证器） | 是否引入？离线降级方式？ | 引入并记录 / 仅 CI 可选 / 不引入 | 项目所有者 | 对应检查器能力 |
| `HD-16` | 目标版本低于已安装版本，或平级重装 | 是否允许降级 / 重装？原因与补偿？ | 允许（记录理由）/ 拒绝 | 项目所有者 | 更新应用 |

决策记录要求：

- `OPEN` 必须在报告与 Issue 中可见；不得用默认值填充。
- 决定后写 `decided_by` / `decided_at` / 理由；影响契约的按 `templates/contract-decision-log.md` 记录。
- 决策不影响已完成的验收；head 变化仍需重新取证。

## 6. 无新证据 / 无来源时的行为

- 有 `OK` 扫描但无新候选：输出“无新候选”，附扫描窗口、来源、游标与过滤计数；**不创建**任务或 Issue。
- 注册表为空：输出“无来源可扫描”，不猜测默认来源。
- 全部来源 `BLOCKED` / `UNKNOWN`：输出“未完成扫描”，列出原因与未覆盖范围；不得写“无新经验”。
- 只有 `UNVERIFIED_ASSUMPTION`：只入报告，不创建实现任务。

## 7. 报告要求

自我完善报告至少包含：

```text
触发语与 edition：
head SHA 与工作区状态：
来源 / 游标 / 扫描窗口 / 过滤计数：
扫描结论：OK / PARTIAL / BLOCKED / UNKNOWN（逐来源）
候选与采纳：lesson_id、content_class、evidence_level、去重 / 冲突状态
已覆盖检查：对应契约 / 代码 / 测试
生成的 Issue / 任务与依赖：
被阻塞项与原因：
人工决策（HD-*）与选项：
未执行项（NOT_RUN / UNKNOWN）及理由：
证据链接：
```

不得把“已规划”写成“已实现”，不得用报告代替任务状态或合并门结论。
