# 项目章程（Project Charter）

> 本章程记录套件演进的既定决策。任务 ID：T-000B。
>
> 2026-10-19 补记：套件现已提供 `local` 与 `github` 两种底座；下文“单用户 / 离线”描述的是最初形态，不代表当前能力边界。底座选择与迁移判据见 [README.md](README.md) 第 2 节。

## 问题与目标用户
- 要解决的问题：
  - 此前启动资料不完整，配置模板中全是占位符，无法直接投入使用；
  - 目标与实现路径不清晰，任务包依赖人工手写；
  - 需要人工干预的环节多，包括每次会话需人工恢复状态、多会话之间的交接依赖人工操作。
- 目标用户 / 场景：使用本套件进行多会话任务编排与演进的开发者。最初形态为单机、离线单用户；当前支持 `local`（纯本地）与 `github`（多人协作）两种底座，底座选择见 [README.md](README.md) 第 2 节。

## 目标与非目标
- 目标：
  - 吸收 obra/superpowers 的方法论特性，转化为本套件自有的 prompts/ 与 templates/ 文件，具体包括：
    - brainstorming 式章程引导；
    - writing-plans 式计划拆解；
    - subagent 驱动执行；
    - 两阶段代码审查；
    - TDD；
    - 验证先于完成。
  - 上述特性不直接并入 superpowers 仓库，而是沉淀为本套件自有资产。
- 非目标：
  - 不接入任何插件市场；
  - 不编写"计划→任务"转换脚本（CLI 已支持该流程，提示词层足够）；
  - 不引入任何第三方依赖。

## 约束与假设
- 平台 / 运行时：纯 Python 标准库，不引入任何第三方依赖。
- 数据与隐私：套件内容保持项目无关、可复用，不绑定任何具体项目。
- 性能 / 可靠性：依赖既有 SQLite 状态层与路径锁机制保障多会话一致性。
- 需验证的假设：方法论特性转化为自有提示词/模板后，仍能在本套件执行链路中生效（通过 validate_kit.py 与测试验证）。
- 里程碑分阶段：
  - 阶段 0：环境配置；
  - 阶段 1：章程引导；
  - 阶段 2：计划拆解；
  - 阶段 3：会话自动引导；
  - 阶段 4：子代理驱动与审查闭环；
  - 阶段 5：收尾验收。

## 初始成功标准
- [ ] validate_kit.py 与 unittest 全绿；
- [ ] 全部演进任务状态达到 VERIFIED；
- [ ] 新增提示词/模板内容保持项目无关。

## 架构决策与替代方案
- 决策：吸收 obra/superpowers 的方法论特性（brainstorming 式章程引导、writing-plans 式计划拆解、subagent 驱动执行、两阶段代码审查、TDD、验证先于完成），转化为本套件自有的 prompts/ 与 templates/ 文件；不把本套件并入 superpowers 仓库。
- 替代方案：并入 superpowers 仓库 —— 已否决。理由：
  - 官方基本不接受新的 skill 贡献；
  - superpowers 无持久状态层，并入必须砍掉本套件的 SQLite 状态与路径锁核心；
  - 离线单用户前提会被其联网插件体系破坏；
  - 演进节奏将受制于上游。
- 取舍 / 风险：自维护方法论文档的持续成本 vs 上游依赖风险；选择自维护，即接受文档自维护成本，换取对状态层、离线前提与演进节奏的完全控制。

## 初始里程碑
- 最小端到端垂直切片：按阶段 0–5 推进，先完成环境配置与章程引导，使章程、计划拆解到执行验证的链路可在套件内闭环运转。
- 验证方法：validate_kit.py 与 unittest 全绿；演进任务逐个推进至 VERIFIED；新增提示词/模板经内容审查确认项目无关。
- 回滚 / 恢复：文档与提示词/模板变更均在独立分支与 worktree 中进行，未通过验证可整体弃用对应分支，不影响 main 与既有状态层。
